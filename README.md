# Cloud Clipboard

Cloud Clipboard syncs your clipboard across devices. It watches the system clipboard on desktop and pushes new clips to the cloud, so text (and other clip types) copied on one machine shows up in your clip history everywhere else, with an optional team-sharing layer for favorites.

The repository contains two apps that share the same backend API:

```
Cloud-Clipboard/
├── cloud-clipboard-web-app/       # Next.js web app: auth, dashboard, API, database
└── cloud-clipboard-desktop-app/   # Electron + React desktop app: clipboard watcher, sync client
```

## How it works

- **Web app** — users sign up / log in (Supabase Auth), manage their devices, and browse/search their synced clip history, favorites, and teams from the browser. It also hosts the REST API and Postgres database (via Prisma) that both the web and desktop clients talk to.
- **Desktop app** — an Electron app that watches the OS clipboard in the background. New clips are pushed to the web app's API and appear in the synced history. On first launch it walks the user through a **device pairing** flow instead of a traditional login.

### Device pairing flow

1. The web dashboard (or the desktop app) requests a short-lived, human-readable pairing code from `POST /api/devices/pair`.
2. The code is entered in the desktop app (or scanned as a QR code), which calls `POST /api/devices/verify`.
3. The server validates the code, issues a long-lived `authToken` for that device, and marks it as paired.
4. The desktop app stores the token locally (`auth.json` in the Electron user-data directory) and uses it as a Bearer token on subsequent API calls (`/api/clips`, `/api/devices/ping`, `/api/devices/me`) to sync clips and report online status.

### Data model

Defined in `cloud-clipboard-web-app/prisma/schema.prisma`:

| Model | Purpose |
|---|---|
| `User` | Account, linked to Supabase auth |
| `Device` | A paired device (web/desktop/mobile), its pairing/auth token, and online status |
| `Clip` | A single clipboard entry (`TEXT`, `IMAGE`, `FILE`, or `CODE`), tied to a user and the device it came from |
| `Favorite` | A saved/pinned clip, optionally shared with a team |
| `Team` / `TeamMember` | Team workspaces with role-based membership (`ADMIN`, `EDITOR`, `VIEWER`) |
| `SharedClip` | A clip shared into a team |
| `Setting` | Per-user preferences (sync frequency, shortcuts, cloud storage limit) |

## Web App — `cloud-clipboard-web-app/`

### Features

- Email/password auth (sign up, sign in, forgot/reset password) via Supabase
- Dashboard with clip history, favorites, and per-device management
- Device pairing (generates and verifies short-lived codes, issues device auth tokens)
- Team spaces for sharing clips with others
- REST API consumed by both the web UI and the desktop app

### Tech Stack

Next.js 15, React 19, TypeScript, Tailwind CSS 4, shadcn/ui + Radix UI, Prisma + PostgreSQL, Supabase (auth + client), Zustand, React Hook Form + Zod, FingerprintJS

### API Routes

| Route | Description |
|---|---|
| `POST/GET /api/users` | Create or fetch a user record |
| `POST/GET/DELETE /api/devices` | Register/update, list, or remove devices for a user |
| `POST /api/devices/pair` | Generate a short-lived pairing code for a new device |
| `POST /api/devices/verify` | Redeem a pairing code for a device auth token |
| `POST /api/devices/me` | Validate a device's auth token and return the associated user/device |
| `PATCH /api/devices/ping` | Heartbeat to mark a device as online and update `lastSeenAt` |
| `POST/GET /api/clips` | Push a new clip (device-authenticated) / fetch a user's clip history |

### Setup

```bash
cd cloud-clipboard-web-app
npm install
```

Create a `.env` file:

```bash
DATABASE_URL=postgresql://...      # pooled connection (e.g. Supabase pooler)
DIRECT_URL=postgresql://...        # direct connection, used for migrations
NEXT_PUBLIC_SUPABASE_URL=your-supabase-project-url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-supabase-anon-key
```

Apply database migrations:

```bash
npx prisma migrate deploy
# or, during development:
npx prisma migrate dev
```

Run the dev server:

```bash
npm run dev
```

The app runs on [http://localhost:3000](http://localhost:3000).

## Desktop App — `cloud-clipboard-desktop-app/`

### Features

- Watches the system clipboard in the background (`clipboard-event`) and automatically uploads new text clips
- Device pairing screen (enter/scan a code generated by the web app) instead of a password login
- Local clip list, settings, and team view mirroring the web dashboard
- Packaged as a native app for macOS, Windows, and Linux via Electron Builder

### Tech Stack

Electron, React 19, TypeScript, Vite, React Router, Tailwind CSS 4, Radix UI, `clipboard-event`, `react-syntax-highlighter`

### Setup

```bash
cd cloud-clipboard-desktop-app
npm install
```

By default the app talks to the web API at `http://localhost:3000`, so run the web app (see above) alongside it during development.

### Development

```bash
npm run dev
```

This runs the Vite dev server and Electron concurrently, with hot reload for the renderer.

### Building distributables

```bash
npm run dist:mac     # macOS (arm64)
npm run dist:win      # Windows (x64)
npm run dist:linux    # Linux (x64)
```

Build configuration lives in `electron-builder.json`.

## Notes

- The desktop app currently points at `http://localhost:3000` for API calls — update the relevant URLs in `src/electron/main.ts` before shipping a production build against a hosted deployment.
- CORS in the API routes is restricted to `http://localhost:5123` (Electron dev), `app://.` (packaged Electron), and `http://localhost:3000` (web) — update the `allowedOrigins` lists if you deploy the web app to a different domain.
